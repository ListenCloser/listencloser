# Design-DNA analysis template

Use this template under #1143 when analyzing an external reference or a historical Listen Closer direction.

The purpose is to extract **decisions and tradeoffs**, not pixels.

---

## Dominant visual idea

What is the one compositional / visual idea visible before details?

What would remain recognizable if brand name and logo disappeared?

## Hierarchy

What wins first, second, third?

How is hierarchy created?

- scale;
- typography;
- contrast;
- position;
- whitespace;
- color;
- motion;
- containment;
- something else.

What is intentionally de-emphasized?

## Typography

Record roles rather than merely font names:

- display role;
- body role;
- utility/control role;
- numeric/data role;
- size contrast;
- weight contrast;
- casing;
- tracking;
- line-height;
- measure;
- rhythm.

What gives the typography character?

## Composition

- grid / layout model;
- symmetry vs asymmetry;
- focal region;
- relationship of copy to product/content;
- density distribution;
- negative-space behavior;
- scrolling / viewport strategy;
- responsive changes.

## Material / surface model

- flat vs layered;
- borders;
- shadows;
- texture;
- translucency;
- radius strategy;
- separation between canvas/content and chrome.

Does the system rely on cards? If so, where are cards actually necessary?

## Color

Describe **proportions and roles**, not only hex values:

- dominant neutral/background;
- body text;
- high-emphasis text;
- accent proportion;
- semantic colors;
- decorative colors;
- state colors;
- light/dark behavior.

What is the smallest number of colors carrying most of the identity?

## Geometry / iconography

- line weights;
- corner/radius language;
- icons: filled/outline/custom/system;
- repeated motifs;
- separators / rules;
- controls / button silhouette;
- logo/mark relationship to the rest of the geometry.

## Product imagery / data

How does the real product/content become visual material?

Does the design show:

- screenshots;
- cropped product fragments;
- abstracted product structure;
- real data;
- illustration;
- photography;
- diagrams;
- nothing at all?

What makes the visual truthful rather than decorative simulation?

## Motion

- ambient vs user-triggered;
- entrance behavior;
- state transitions;
- duration/easing character;
- number of simultaneous moving regions;
- reduced-motion behavior;
- whether motion carries required meaning.

## Voice / copy

- specificity;
- sentence length;
- metaphor use;
- confidence level;
- jargon level;
- CTA language;
- personality;
- relationship between marketing voice and in-product voice.

## Tradeoffs

What does this design system make worse, harder, less visible, or less flexible in order to achieve its strengths?

Do not write `none`.

## AI-template / fashion check

Which parts are now common enough that copying them would make Listen Closer more generic?

Examples to consider, not automatic failures:

- huge centered headline;
- purple/blue glow;
- pill badge;
- glass cards;
- bento grid;
- three feature cards;
- dock navigation;
- excessive rounded rectangles;
- default monochrome sans typography;
- background grid/noise;
- animated text effects.

## Transferable decisions for Listen Closer

Write 3–5 decisions in this form:

```text

When ...

Do ...

Because ...

...

LISTEN CLOSER TEST:
On <fixed surface>, compare <A> vs <B> using <evaluation criterion>.
```

## Do not copy

Name the brand signatures, irrelevant product metaphors, proprietary assets, and context-specific choices that should not transfer.

## Fit by surface

Rate with short rationale:

- signed-out landing: `strong / possible / weak`;
- empty state: `strong / possible / weak`;
- populated workspace: `strong / possible / weak`;
- Breakdown / Ask: `strong / possible / weak`;
- favicon / mark: `strong / possible / weak`.

## Final research status

Choose one:

- **REFERENCE** — contains useful transferable decisions;
- **DEEP REFERENCE** — should materially inform one or more candidate directions;
- **CONTRAST** — useful primarily as an example of what not to do;
- **DROP** — adds little after analysis.

This status is about research value, not design quality in the abstract.
