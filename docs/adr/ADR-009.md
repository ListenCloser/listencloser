# ADR-009 — Free Three-Plane Runtime with One Release Contract

Status: accepted
Date: 2026-08-11
Owners: product

## Context

The application needs static/web delivery, private durable data, authentication,
and CPU-heavy Python audio processing. The budget constraint is zero recurring
infrastructure cost. The prototype spread those responsibilities across Vercel,
Supabase, and an Oracle Free Tier VM, but deployments were mutable: the canonical
domain pointed at another project, migrations were not executed reliably, and the
VM could run an old deploy script while GitHub reported a newer commit.

## Decision

Keep the three providers because each supplies a distinct free capability that
the others cannot replace economically:

- Vercel serves the Next.js workspace and authenticated proxy routes.
- Supabase owns Auth, Postgres, the job queue, and private artifact storage.
- Oracle runs one FastAPI container and one bounded audio worker container.

Treat them as one release. Database migration/verification happens first; the VM
then deploys an exact Git SHA and reports that SHA from readiness; Vercel deploys
the same merged `main`; a real authenticated audio smoke test is the final gate.
The canonical domain is configuration, not inferred from a preview URL.

Browser uploads remain proxy-based and are honestly limited to 4 MB in the
current slice. The next ingestion change should upload directly to owner-scoped
private Supabase storage and finalize metadata through the API, avoiding Vercel's
body limit without adding another service.

## Alternatives considered

- **Everything on Oracle:** fewer providers, but loses free preview deployments
  and makes the single VM a web, API, worker, TLS, and release bottleneck.
- **Everything on Vercel/Supabase:** simpler operations, but neither free tier is
  suitable for Basic Pitch/TensorFlow and long-running audio jobs.
- **GitHub Actions as the worker:** free for limited CI, but not an interactive,
  durable user job runtime and couples product availability to CI quotas.
- **Additional queue or orchestration service:** rejected until Postgres leases
  become a measured bottleneck.

## Consequences

- Three credentials/configuration surfaces remain, but code verifies their joint
  state instead of assuming it.
- `SUPABASE_DB_URL` is a required GitHub Actions secret.
- The VM must be reachable through the configured HTTPS backend endpoint.
- Production is not healthy unless database, private storage, required worker
  capability, release SHA, and real audio smoke all agree.
- Direct-to-Supabase upload and immutable prebuilt container images remain
  worthwhile simplifications, not prerequisites for the current small workload.

## Validation

- Clean-database migration CI passes.
- `/health/ready` reports the requested release SHA and usable DB/storage.
- `/health/queue` sees a recent worker advertising `understand:1.0`.
- The canonical Vercel URL completes the real-audio smoke test and reopens the
  resulting persisted work.
