# ADR-002 — Global Timeline, Transport, and Selection

Status: accepted
Date: 2026-07-28
Owners: orchestrator

## Context

The current app has per-component playback state: each representation (piano roll, score, waveform) manages its own audio context, and transport is ad-hoc. Multiple audio elements can play simultaneously with no coordination. There is no shared selection connecting the piano roll to the score to the waveform — selecting a note in one view does not highlight it in others. Playback position is not synchronized across representations.

## Decision

One shared timeline maps between seconds, samples, beats, measures, MIDI ticks, and score positions via explicit alignment artifacts. One global transport owns play state, position, loop region, tempo, and active source. One shared selection synchronizes all representations: selecting a span, note, or region in any representation immediately highlights it in all others. The timeline and transport are domain-level stores that all visual representations subscribe to.

## Invariants affected

- All representations observe the same transport state (play/pause, position, tempo, loop bounds).
- All representations observe the same selection state.
- Switching the active source preserves position only when an alignment artifact exists between old and new source.
- Only one source can be active (playing or selected for playback) at a time.
- Transport position can only advance within the bounds of the active source's duration.

## Alternatives considered

- **Per-representation transport with loose synchronization**: Each component manages its own transport, and events fire to loosely sync others. Rejected because drift, race conditions, and inconsistent state across components.
- **Audio-context-only transport (Web Audio API clock)**: Use only the audio clock for transport. Rejected because many representations are visual (piano roll, score) and need musical time, not just seconds.
- **Embedded transport in each representation component**: Each component duplicates transport logic. Rejected because divergence and inability to coordinate global operations (e.g., loop across all views).

## Consequences

- Requires `Alignment` domain entity: maps a source position to timeline coordinates (seconds, samples, beats, measures, ticks, score position).
- Requires a global transport store: holds play state, position, loop region, tempo, active source.
- Requires a global selection store: holds selected span and selected entity IDs.
- Existing per-component playback must be replaced or wrapped.
- Representations must subscribe to store changes via hooks or observers.
- Tempo changes must propagate through the alignment layer to update musical-time positions.

## Migration

1. Introduce transport and selection stores as separate modules (e.g., `stores/useTransportStore`, `stores/useSelectionStore`).
2. Representations subscribe to these stores via hooks (`useTransport`, `useSelection`).
3. Alignments are computed from audio-analysis metadata and stored as part of the transcription output.
4. Existing per-component playback continues to function until stores are fully wired. During transition, the global transport can emit events that the old playback system ignores.
5. Once all representations consume the stores, remove old per-component playback state.

## Rollback

Old per-component playback can coexist during transition. Representations that have not yet migrated continue to use their own transport. The global transport store can be removed or disabled without affecting unmigrated components.

## Validation

- Playing audio moves the playhead in the piano roll, score view, waveform, and any other representation simultaneously.
- Pausing audio stops all playheads at the same position.
- Selecting a note span in the piano roll highlights the corresponding notes in the score and waveform.
- Selecting a section in the score highlights the corresponding audio region in the waveform.
- Changing the loop region in one view updates the loop visualization in all views.
- Switching the active source to one without an alignment for the current position resets position to 0.

## Supersedes / superseded by

- Supersedes ad-hoc per-component playback state in the reference implementation.
- Superseded by: none.
