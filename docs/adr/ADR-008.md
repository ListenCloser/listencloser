# ADR-008 — Canonical Route is Root, Old Shell Must Be Replaced

Status: accepted
Date: 2026-07-29
Owners: orchestrator

## Context

PR #165 added a workspace at `/workspace` while leaving the old `Studio.tsx` tabbed shell at the root route `/`. This created a dual-application: the old product remained the default experience, and the new workspace was hidden on a secondary route. The v2 delivery manual explicitly forbids this pattern.

There are no production users. Legacy compatibility is not required.

## Decision

The root route `/` must be the canonical music workspace. The old `Studio.tsx` tabbed shell and all associated page-per-feature components must be deleted. The workspace shell currently at `/workspace` will become the root experience.

## Invariants affected

- Product Contract: "The canonical authenticated route must open this workspace or a project/library entry point that opens it immediately."
- Technical End State: "No duplicate old/new app shells."

## Alternatives considered

1. **Keep both routes, add redirect** — leaves dead code, violates clean-slate mandate
2. **Feature flag** — acceptable as temporary bridge during active rebuild, but each PR must move toward deletion
3. **Replace root immediately** — chosen; old code deleted in R2

## Consequences

- Old `Studio.tsx`, tab components, and associated page layouts will be deleted in R2
- All old `/music/*` API proxy routes may be deleted or migrated
- R1 adds a failing journey test proving root does not yet show the workspace
- R1 captures baseline screenshots as pre-replacement evidence

## Migration

R1 (this PR): Baseline screenshots + failing test + this ADR
R2: Replace root shell with canonical workspace, delete old shell

## Rollback

Revert R2 commit to restore old shell. R1 adds no behavioral changes.

## Validation

R1 test must fail on current root (no workspace at /) and pass after R2.

## Supersedes / superseded by

Supersedes PR #165's "preserve existing behavior" approach.
