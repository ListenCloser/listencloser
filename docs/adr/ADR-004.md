# ADR-004 — Structured Entities and Insights

Status: accepted
Date: 2026-07-28
Owners: orchestrator

## Context

The current app represents notes as anonymous JSON objects `{pitch, start, end, velocity}` within a flat array. Analysis results (key, tempo, chords) are inline fields on the transcription result object. There are no typed identifiers, no spans as first-class concepts, and no way to query across the library — e.g., "find all C major chords across my projects" or "show me the evidence and confidence for this key detection." Analysis outputs are opaque blobs, not structured claims.

## Decision

Musical objects are typed entities with explicit spans (time ranges) and identifiers. Analysis produces insights — structured claims with evidence, scope, provenance, and confidence. Insights reference the entities and artifact version they describe. Both entities and insights are stored in Postgres as queryable tables, enabling library-wide searches, aggregation, and cross-project queries.

## Invariants affected

- Entities identify musical objects (notes, chords, beats, measures, phrases, sections, cadences, motifs) with typed schemas, explicit spans, and stable identifiers.
- Insights are claims with evidence, not raw prose. Every insight includes: `type`, `scope` (span), `confidence` (0–1), `provenance` (which analysis job, which model), `evidence` (structured supporting data).
- Confidence is always present on every insight.
- Entities belong to an artifact version. Insights reference entities and their parent version.

## Alternatives considered

- **Inline metadata on artifacts**: Embed analysis results directly in the artifact JSON. Rejected because it makes cross-library queries impossible and conflates raw data with analysis claims.
- **Generic key-value tags**: Tag artifacts with arbitrary key-value pairs. Rejected because tags lack structure (no spans, no confidence, no provenance) and cannot express relationships between entities.
- **Graph-only storage**: Store entities and insights in a graph database. Rejected because the primary query patterns are range scans on spans and aggregations, which Postgres handles efficiently with proper indexing. Graph traversal is a secondary concern that can be added later.

## Consequences

- Requires `entities` table: `id`, `artifact_version_id`, `type` (enum: note, chord, beat, measure, phrase, section, cadence, motif), `span` (tstzrange or custom range type), `data` (JSONB with typed payload).
- Requires `insights` table: `id`, `artifact_version_id`, `entity_id` (nullable, for entity-level insights), `type`, `span`, `confidence`, `provenance` (job_id, model name, version), `evidence` (JSONB), `scope` (span or entity reference).
- Analysis outputs must be structured (typed Insight records), not free text or opaque JSON.
- Query capabilities enable library-wide searches: "all chord progressions in C major," "average confidence of key detection across my library," etc.
- Postgres indexes on `type`, `span`, and `confidence` are required for performant queries at scale.

## Migration

1. Music21 analysis outputs map to Insight records (key detection → key insight, chord detection → chord insights with per-chord entities).
2. Transcription notes map to Entity records (MIDI note → note entity with pitch, velocity, span).
3. Existing analysis data in transcription JSON must be backfilled: parse old inline fields, create corresponding entity and insight rows, and link them to the parent artifact version.
4. Frontend analysis display transitions from reading inline JSON to querying entities/insights endpoints.
5. Display insight confidence, evidence, and method alongside analysis results.

## Rollback

Existing analysis display continues to work with old data format. Entities and insights tables are additive — they do not alter existing artifact data. Old inline analysis fields remain in the transcription JSON and can be read directly if the new tables are dropped or queries fail.

## Validation

- Query "all chord progressions in C major" returns results across projects, not just within a single artifact.
- Insight display shows confidence (e.g., "Key: C major, confidence: 0.92") and method (e.g., "Detected by music21 key analyzer v0.4").
- Selecting a chord in the piano roll shows its entity ID, span, and linked insights.
- Backfilled data matches original inline analysis values exactly.

## Supersedes / superseded by

- Supersedes inline analysis fields on transcription objects in the reference implementation.
- Superseded by: none.
